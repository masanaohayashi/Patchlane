# 検証範囲

`swift test -j 1` は設定、ゲイン、ルーティング、モード切り替え、再接続判断などを検証する。

`scripts/test-driver.sh` は実際のHALバンドルを模擬ホストで読み込み、チャンネル構成、音量・ミュート、時刻付き入出力、再起動、補間、共有メモリの読み取り専用性を検証する。2ch DSPから共有メモリを経て実際の出力コールバック処理へ渡すテスト、2ch／8ch公開領域の分離テストも含む。

`scripts/test-uninstaller.py` は一時ボリューム内で削除、再実行、他社製品・設定の保護、ID不一致時の拒否を検証する。実システムは削除しない。

`Tools` は機器診断や遅延計測用のソース。物理経路の計測には対応する接続・配線が必要。単体テストの成功だけでは、すべての機器の聴感・長時間安定性・アナログ往復遅延を保証しない。

`nice -n 15 bash scripts/test-realtime.sh` はビルド済みドライバーを使い、通常ミキサーのrender、2ch／8ch DSP、共有出力IOProc、HALの音声・時刻コールバック中のmutex、heap確保・解放、主要な待機APIをdyld interposeで検出する。検出器自体も子プロセスのmutex取得で検証する。実機AUHAL内部の処理や全OS APIを網羅するものではない。

## ステレオダイポール

`bash scripts/test-dipole.sh` はNEON版とスカラー版をRelease相当の最適化で検証する。既知の非最小位相FIR `[0.5, 1]` を `[1, 0.5]` に再構成する解析解との一致、複数配置・全対応レートの目標振幅特性と先頭64サンプル以内のインパルスピーク、時間領域インパルスとの一致、最適化前の4経路・全スペクトル版との一致、全対応レートの低域Mid/Side保持、20Hz/1kHz/20kHzの±12dB GEQ、設定の並行公開を検査し、CPUベンチマークを出力する。

2026-10-04の開発機・32フレームコールバックで、10秒分の音声のFFT部分は約0.021秒（4経路参照版約0.049秒、約2.3倍）。31バンド全部有効時は約0.034秒、1出力のDSPは1コアの約0.34%。スカラー版の全バンド有効時は約0.041秒。値はDSP単体の測定で、Patchlane全体や実機ドライバー経路のCPU表示を意味しない。

`swift test -j 1` にプリセット保存/更新/削除、旧設定移行、出力別割り当て、処理キャッシュ、可変ブロック、出力間の独立性、画面のオフスクリーン描画の検証を追加した。`scripts/test-realtime.sh` は通常renderと2ch/8ch共有出力にダイポール＋GEQを有効にして、FFTブロック境界を越えるコールバックの確保・解放・ロック・待機を検査する。

物理スピーカーでのキャンセル量、音色、頭の移動、長時間動作は別途実環境での検証が必要。

最小位相方式はMid/Sideを個別に対数振幅から再構成する一般的なhomomorphic法。旧方式の4096サンプルの共通設計遅延を廃止し、FFTバッファは256サンプル。`swift test` では実ストリーミングのインパルスピークが全対応レートで20ms以内に到達することと、中央音の音量を自動で減衰しないことを検査する。最小位相化は元のモード間の位相差を保持しないため、キャンセル量が従来と同じであることは保証しない。

出力デバイスのDipole状態はCore Audio UIDごとに記録する。回帰テストでは、外部ヘッドフォンの「JC Default」オン → 初回の内蔵スピーカーではオフ → ヘッドフォンに戻るとオン＋同プリセットの復元、再起動後の復元、別のMain/Aux枠での同機器選択、同UIDへの設定変更の同期、未選択機器に対するプリセット更新/削除、旧ファイル移行、未選択機器の保存値検証を実機HALに接続せず確認する。
