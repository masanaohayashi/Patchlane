# 検証範囲

`swift test -j 1` は設定、ゲイン、ルーティング、モード切り替え、再接続判断などを検証する。

`scripts/test-driver.sh` は実際のHALバンドルを模擬ホストで読み込み、チャンネル構成、音量・ミュート、時刻付き入出力、再起動、補間、共有メモリの読み取り専用性を検証する。2ch DSPから共有メモリを経て実際の出力コールバック処理へ渡すテスト、2ch／8ch公開領域の分離テストも含む。

`scripts/test-uninstaller.py` は一時ボリューム内で削除、再実行、他社製品・設定の保護、ID不一致時の拒否を検証する。実システムは削除しない。

`Tools` は機器診断や遅延計測用のソース。物理経路の計測には対応する接続・配線が必要。単体テストの成功だけでは、すべての機器の聴感・長時間安定性・アナログ往復遅延を保証しない。

`nice -n 15 bash scripts/test-realtime.sh` はビルド済みドライバーを使い、通常ミキサーのrender、2ch／8ch DSP、共有出力IOProc、HALの音声・時刻コールバック中のmutex、heap確保・解放、主要な待機APIをdyld interposeで検出する。検出器自体も子プロセスのmutex取得で検証する。実機AUHAL内部の処理や全OS APIを網羅するものではない。

## ステレオダイポール

`bash scripts/test-dipole.sh` はNEON版とスカラー版をRelease相当の最適化で検証する。解析解 `[0.5, 1]` → `[1, 0.5]` の最小位相再構成、複数配置・全対応レートの有限な振幅特性と先頭64サンプル以内のピーク、256／512タップの長さと末尾ゼロ、追加バッファなしの実ストリーミングインパルス、独立した4経路の直接畳み込みとの一致、バイパス後の履歴リセット、20Hz/1kHz/20kHzの±12dB GEQ、設定の並行公開を検査し、CPUベンチマークを出力する。短縮後の目標振幅からの誤差も表示する。

2026-10-04の開発機・32フレームコールバックでは、NEON版の両モードFIR＋31バンドGEQで10秒分の音声処理が44.1kHzで約0.030秒（1出力・1コアの約0.30%）、96kHzで約0.096秒（約0.96%）。同条件のスカラー版は約1.71%／8.30%。DSP単体の測定で、アプリ全体のCPU表示ではない。複数配置・全対応レートの測定点で、短縮による目標振幅からの最大差は約3.75dBだった。

`swift test -j 1` にプリセット保存/更新/削除、旧設定移行、出力別割り当て、処理キャッシュ、可変ブロック、出力間の独立性、画面のオフスクリーン描画の検証を追加した。`scripts/test-realtime.sh` は通常renderと2ch/8ch共有出力にダイポール＋GEQを有効にして、FIR履歴のリング境界を越えるコールバックの確保・解放・ロック・待機を検査する。

物理スピーカーでのキャンセル量、音色、頭の移動、長時間動作は別途実環境での検証が必要。

最小位相方式はMid/Sideを個別に対数振幅から再構成する一般的なhomomorphic法。旧方式の4096サンプルの共通設計遅延を廃止し、直接畳み込みにより追加バッファは0サンプル。FIRは44.1／48kHzで256タップ、88.2／96kHzで512タップ、最後の1/8を半コサインでフェードする。`swift test` では実ストリーミングのインパルスピークが全対応レートで入力と同じ0番サンプルに到達することと、中央音の音量を自動で減衰しないことを検査する。最小位相化は元のモード間の位相差を保持しないため、キャンセル量が従来と同じであることは保証しない。

出力デバイスのDipole状態はCore Audio UIDごとに記録する。回帰テストでは、外部ヘッドフォンの「JC Default」オン → 初回の内蔵スピーカーではオフ → ヘッドフォンに戻るとオン＋同プリセットの復元、再起動後の復元、別のMain/Aux枠での同機器選択、同UIDへの設定変更の同期、未選択機器に対するプリセット更新/削除、旧ファイル移行、未選択機器の保存値検証を実機HALに接続せず確認する。
